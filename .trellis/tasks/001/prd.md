# 001 需求记录（回溯 PRD）

## 背景

上游项目来自 `hdeman3/HDEG`，当前改造仓库为 `hz121315/HDEG`。会话先完成环境准备、Prompt/API 流程分析，再对比本地集成版 `RJ最深层工作流.bat` 及其 PowerShell 编排。

集成版以每作品独立进程、临时目录和结果回收实现批处理；用户要求在当前 HDEG 上吸收实用能力，保留原来的台本、术语、角色和世界观，不直接搬用多进程方案。

## 最终确认的行为

### 文件判定

| 条件 | 动作 |
| --- | --- |
| 同名 A.lrc 存在，不论语言、完整性和大小 | 整轨跳过 |
| A.lrc 不存在，A.ja.lrc 存在 | 不重转录，直接读日文留档翻译 |
| 两者均不存在 | 转录、保留日文留档，再生成译文 |

用户明确推翻早期“检测 LRC 是中文才跳过”的设计。本规则可能跳过历史日文 LRC，这是已解释并接受的语义，不允许后续擅自加语言判断或内容比对。

### 流水线与持久化

- 一部作品转录就绪后即可分析、翻译；不等输入目录内所有作品全部结束。
- 新完成的转录及时保留为 A.ja.lrc，已完成的译文及时写 A.lrc。
- 翻译以整条音轨为最小提交单元；每 100 行是 API 分块，不是逐块写目标文件。
- 目标字幕原子写，避免翻译写回被中断留下半截文件。
- 中断后保留已经落盘的成果，不要求行级／块级恢复，不建立复杂逐文件状态机。

### 并发与界面

- 只有一个承担编排与翻译的 HDEG 主进程，翻译采用线程池。
- infer.exe 仍是外部转录引擎子进程；进度窗可额外启动 PowerShell，但不得承担翻译。
- 同时翻译的作品数默认上限 10，音轨数另由 translation_parallel 控制。
- 每作品显示窗口应后台最小化启动，不抢焦点。
- 支持一次拖入多个目录：最终选择 B 方案，共享流水线和翻译池，而不是每个目录全部做完才处理下一个。

### 保留与补充能力

- 保留按作品加载的台本、术语、ASR alias、角色／世界观，以及可选润色。
- 同一作品下不同子目录的同名音轨应隔离，不能覆盖 ASR 样本或误用台本。
- 支持可配置 RJ 向上查找深度。
- 支持“汉化／漢化”后缀文件跳过开关。
- 来源为视频时额外生成 SRT/VTT，而不只对已有字幕同步文本。
- 转录参数以 config.json 为唯一业务配置来源，extra_args 透传到 infer；不能因 BAT 写死参数让配置失效。
- 打包输出到项目根 `temp/`，而非系统 `%TEMP%`；包含使用文档，重要参数靠前。

## 范围边界

本任务不要求改造远程服务本身、不保证 GPU 显存被占满、不承诺某一批大小适合所有显卡；不改变模型提示词的内容政策；不实现每作品独立翻译进程。

未确认的新参数／功能不得自动扩展。`transcription.auto_tune` 是历史提交夹带的已有变更，记录实际行为，但不视为本任务最初确认的要求。

## 验收目标（不是已通过声明）

1. BAT 不直接调用 infer，转录参数能从发布配置传至引擎。
2. A.ja.lrc 无 A.lrc 时不产生占位 A.lrc；翻译失败仍无目标。
3. 多作品实际出现“作品 A 翻译启动早于作品 B 转录结束”。
4. 多根共享作品／音轨上限，已有目标只跳过一次，不漏未完成源。
5. 同名音轨上下文可区分，跨作品请求不携带另一作品内容。
6. 进度窗有真实进度，流式模式保留原日志、报告和重试契约。
7. 成品中 pyopenjtalk、numpy 和词典可用；仅打包体积变化不算验证。

现状差距见 verification.md。
